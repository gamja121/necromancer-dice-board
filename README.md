# 네크로멘서 오브 다이스 — 프로젝트 현황

정리일: 2026-09-23. 저장소 `gamja121/necromancer-dice-board`의 `main`을 읽고, 제작자가 최근 대화에서 확정한 방향을 함께 정리했다. 구현, 확정 기획, 미결정을 구분한다.

## 프로젝트 방향

주사위로 외곽 타일을 이동하고, 전투 직전에 출전 마물을 편성하는 게임. 마물의 낙인·군단·패시브를 조합한다. **V1은 폐기**했다. 현재 저장소의 HTML/JavaScript V2 화면은 검증용 프로토타입이며, 최종 제작은 **Unity로 전환할 계획**이다.

## 제작자가 확정한 방향

- 내 마물이 전투에서 한 번 죽으면 **보유 목록에서 영구 제거**한다.
- 집에서는 덱을 짜지 않고 타일을 바꾼다. **전투 진입 직전에** 출전 덱을 편성한다.
- 외곽을 한 바퀴 돌면 타일의 **위치와 개수**가 변한다.
- 주사위 제어 아이디어는 추가 주사위를 굴려 고르기와 재굴림이다. 주사위 제어 카드는 **소비형**이다.
- 보상 후보는 마물 카드, 낙인 구슬, 주사위 제어 카드, 전투 버프다.
- 유산 시스템은 미정이다. 기본 맵의 타일 수는 제작자가 제공한 이미지로 정했으며, 현재 코드의 타일별 수량과 최종 이미지가 일치하는지 대조해야 한다.

## 구현과 기획의 차이

1. `v2-rules.js`는 전투 중 사망을 기록하지만, 전사한 내 마물을 보유 목록에서 영구 제거하는 통합 흐름은 확인되지 않았다.
2. 영혼 수확 성공 애니메이션 뒤 맵으로 돌아가는 코드는 있으나, 영입 마물을 보유 목록에 저장하는 코드는 확인되지 않았다.
3. 맵에는 수동 타일 재생성이 있지만, 한 바퀴 완료를 조건으로 타일 위치·개수를 변경하는 규칙은 별도 구현이 필요하다.
4. 맵·집 보유 목록은 시험용 `sessionStorage`, 전투 이어하기는 별도 `localStorage`를 쓴다. 획득·사망·소비품·맵 변경을 하나로 묶는 원정 상태가 없다.
5. 보상 4종의 실제 지급·소모, 인플레이션 억제, 유산 시스템, Unity 이관은 아직 완결된 구현으로 확인되지 않는다.

## 다음 작업 순서 제안

1. 보유 마물의 개체 ID·낙인 눈금·생사, 소비품, 타일 배치, 현재 위치, 보상을 담는 단일 원정 상태를 정의한다.
2. 전투 결과를 원정 상태에 반영해 영구 사망과 신규 영입을 저장하고 재시작 후에도 유지되는지 확인한다.
3. 기본 맵 이미지와 코드의 타일별 수량을 대조하고, 한 바퀴 완료 시 변경 규칙을 확정한다.
4. 보상 선택과 주사위 제어 카드의 사용 시점을 정해 짧은 원정 한 회를 끝까지 플레이한다.
5. 검증된 규칙·데이터·에셋의 Unity 이관 범위를 결정한다.

## 협업 기준 파일

- `GAME_DESIGN_RULES.md`: 현재 상세 전투 규칙

- `v2-rules.js`: 전투 판정과 스냅샷
- `v2-map-practice.js`: 맵과 출전 편성 시험
